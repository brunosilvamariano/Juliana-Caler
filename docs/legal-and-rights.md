# Legal, Rights & Delivery Guide

This guide separates **framework ownership**, **client usage**, **third-party rights** and **deployment obligations**. It is operational documentation, not a substitute for a lawyer reviewing a specific commercial agreement.

## Before sending source code to a client
- Confirm in writing what the client is buying: finished website usage, maintenance access, source delivery, exclusivity, or IP assignment.
- Do not describe the Framework as transferred unless that is intentionally agreed.
- Keep `LICENSE`, `COPYRIGHT.md` and `THIRD_PARTY_NOTICES.md` in authorized source deliveries.
- Check licenses for every new font, photo, video, icon, library and client asset.

## Recommended contract topics
A project contract/proposal should independently address: scope, deliverables, payment, revision limits, acceptance, deadlines, client responsibilities, hosting/domain, maintenance, warranties, liability, confidentiality, portfolio rights, data/privacy responsibilities, third-party services, termination, IP ownership and the exact license granted to the client.

## Privacy/LGPD
The current static framework does not itself create a complete privacy compliance program. If a project later adds analytics, cookies, forms, CRM, pixels, user accounts or other personal-data processing, perform a project-specific LGPD/privacy review and add the necessary notices, consent/legal-basis flows and processor/controller documentation.

## Brand and asset hygiene
Never assume an image, logo, font, icon or copied interface is reusable merely because it is publicly accessible. Keep proof of license/permission for production assets when relevant.

## No “absolute protection”
No repository file can prevent copying by itself or guarantee enforceability in every situation. Protection is strongest when source notices, access control, contracts, invoices, authorship history, backups and third-party license records are maintained consistently.
